## Request flow (to implement and document)

**Products:** Browser → `GET /api/products` → `src/lib/products.ts` → JSON array of three products.

**Checkout:** Browser checkout page → `POST /api/checkout` `{ userId, items: [{ productId, quantity }] }` → validate → load catalogue → resolve unit prices **only** from the server catalogue → `subtotal = Σ(unitPrice * quantity)` → `discount = calculateDiscount(subtotal)` → `total = subtotal - discount` → `{ "total": number }`.

Checkout UI must not treat a client-computed price as authoritative.

---

## Checkout validation (HTTP 400 `{ "error": "..." }`)

Reject: malformed JSON; missing/non-object body; empty or non-string `userId`; missing/non-array/`[]` `items`; missing `productId`/`quantity`; non-positive-integer `quantity` (including 0, negative, fractional, missing, wrong type); unknown `productId`; extra client `price` ignored if present (never used).

Success: HTTP 200 `{ "total": number }` only.

Example valid total: one Enamel Mug (`12.5`) + one Canvas Tote (`18.0`) → `30.5` (discount 0).

## UI (intentionally small)

- Home: heading, 1–2 sentence description, link/button to `/checkout`.
- Checkout: list three products from the API, quantity controls (default 0 or empty; only include items with quantity ≥ 1 in the POST body so we do not send invalid zeros), submit, show total or error text.
- Default `userId`: `"guest"` (no login field required).
- Styling: `globals.css` only; system font stack; one accent (e.g. a single blue); centered max-width; rounded cards/buttons; consistent padding.

## Tests (small)

1. Placeholder: `calculateDiscount(100) === 0`.
2. Catalogue has exactly three ids `prod-001` … `prod-003` with the required prices.
3. Valid cart total uses server prices (e.g. 2× mug = `25`).
4. `calculateDiscount` is invoked on the checkout path (total = subtotal − stub 0).
5. Rejects: invalid quantity, unknown product, empty items, empty `userId`.

HTTP 400 JSON shape is covered by testing the shared checkout helper’s error results; the route maps those to 400. Malformed JSON is handled in the route (`try/catch` parse → 400).

Do not add Playwright/Cypress.
